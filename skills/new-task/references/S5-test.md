# S5 测试

> **暂留空**：以下是最小骨架，待与用户细化。

**目标**：用测试验证 `DS` 契约，而不是只验证"跑通了"。
**计划目录**：`.planning/plan4_Test/`
**产物目录**：`.planning/plan4_Test/output/`

## 子步

### S5-1 写测试

- 读 S3 的 `test-points.md` 与 `DS`；写成正式 `TC-1..n`（字段见 `artifact-templates.md`）。
- 每个 `TC` 标明验证的 `DS`（可加 `REQ` / `IF`）。
- 覆盖边界：空、重复、超时、部分失败、乱序。

### S5-2 跑测试

- 跑全量；记录 pass / fail / not-run。
- **对着契约验，不是对着实现验**。

### S5-3 覆盖缺口

- 缺 `TC`、`TC` 没验证契约、边界没覆盖 → **默认必须补**。
- 用户要跳过 → 缺口必须进风险表并拿到出口；不能一次弹框豁免。

### S5-4 测试代码复审 + 收尾

- 测试代码的 diff 过 `code-review-expert`；**Fix all，P0~P3 全修**。
- 复盘拷问（`grilling` 固定一轮，对象 = 测试清单与结果）。
- 逐条风险确认。
- 问："测试完成，是否切到 `plan5_Review`？"→ 建 `output/`、写临时计划（含恢复入口）、切 active、提示**强制 `/clear`** 后输入 `/new-task 继续`。
