# S5 测试

**目标**：用测试验证 `REQ` / `IF` / `DS` 的契约，而不是只验证"跑通了"。
**产物目录**：`04_Test/output/`
**计划目录**：`.planning/plan4_Test/`

## 开场

1. 读 S3 的 `IF` / `DS` 与 S4 的 diff。
2. 建临时计划 `plan4_Test`，切 `.active_plan`。
3. 打 S5 横幅。

## 写测试

- 按 `TC-1..n` 写；每个 `TC` 必须标明它验证的 `REQ` / `IF` / `DS`（字段见 `artifact-templates.md`）。
- 覆盖边界：空、重复、超时、部分失败、乱序。
- **对着契约验，不是对着实现验**：覆盖率骗不过契约。

## 覆盖缺口

- 缺 `TC`（某个 `REQ` 没测）、`TC` 没验证契约、边界没覆盖 → **默认必须补**。
- 用户要跳过：缺口**必须进风险表**，并拿到出口（接收 / 解决 / 重新确认）；**不能靠一次弹框豁免**。

## 测试代码复审

- 测试代码的 diff 也要过 `code-review-expert`：
  - 结论回写 `findings.md`；
  - 按结论修复，不自动统一全修；
  - 未修复的进风险表拿出口。

## 收尾

- 复盘拷问（`grilling` 固定一轮，对象 = 测试清单与结果）：抓"测了错的东西"、断言太弱、缺口隐瞒。
- 逐条风险确认（测试风险）。
- 产出：`04_Test/output/`（测试清单 + 结果 + 缺口 + 缺口出口）。
- **人工确认**：问"测试完成，是否切到 `plan5_Review` 并 `/clear`？"
  - 首项「切换并建议 /clear」(推荐) / 「切换但不 clear」/「先停」。
