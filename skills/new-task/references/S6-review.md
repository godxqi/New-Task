# S6 审查

**目标**：对账整条 ID 链，做最终收缩，给出可验收的结论。
**产物目录**：`05_Review/output/`
**计划目录**：`.planning/plan5_Review/`

## 开场

1. 读前五个阶段的 `output/` 与各自的 `task_plan.md`。
2. 建临时计划 `plan5_Review`，切 `.active_plan`。
3. 打 S6 横幅。

## 对账

逐条检查：

- **需求**：每个 `REQ` 有 `IF` / `DS` / `TC`；
- **接口**：每个 `IF` 有 `DS`；
- **数据**：每个 `DM` 有 `DS`；
- **详设**：每个 `DS` 有 `WI`；
- **工作项**：每个 `WI` 有 `RV`；
- **ADR**：每条架构级决策有 ADR，且索引在计划里；
- **断点**：列出来，标明该回哪一阶段补。

产出 `reconciliation.md`（字段见 `artifact-templates.md`）。

## 收缩

- 调一次 `ponytail:ponytail-review`（只吃 diff、只查过度设计）。
- 按意见修改：只收缩、不夹带功能变更；拒绝写明理由。

## 完成判据

- [ ] 六个阶段都有独立计划与 `output/`
- [ ] 每条审查行要么打勾、要么写明未执行理由
- [ ] 每个阶段的风险表每条都有出口或未给出口的理由
- [ ] ID 链 `REQ → IF → DM → DS → WI → TC` 无断点
- [ ] ADR 索引完整
- [ ] 未验证项如实列出

## 收尾

- 复盘拷问（`grilling` 固定一轮，对象 = 对账结果 + ponytail 结论）。
- 逐条风险确认（最终验收）。
- 产出最终结论：**通过** / **打回**（打回写明回哪一阶段、补什么）。
