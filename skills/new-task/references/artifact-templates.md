# 产物固定字段（每个阶段都按这个写）

> 目的：让「ID 链可追」有机械抓手，不靠模型自觉。字段不许空着；不适用的写 `N/A` 并给一句理由。

## 通用规则

- 文件名纯 ASCII；ID 连续、不重排。
- 每个产物抬头写：**所属阶段 / 生成日期 / 输入来源**。
- 表格里每个 ID 必须能指回上游（见「ID 体系」）。

## ID 体系

**三条链**：

- **设计链**：`REQ → IF → DM → DS`
- **实施链**：`DS → WI → RV`
- **验证链**：`DS → TC`

`WI` 与 `TC` 是 `DS` 下的两条并列支线，**不是上下游**；`WI` 的输入不含 `TC`。

| 前缀 | 含义 | 产生于 | 指向 |
|---|---|---|---|
| `REQ-n` | 功能需求 | S1 | — |
| `NFR-n` | 非功能需求 / 质量属性目标 | S1 / S2 | — |
| `IF-n` | 接口 / 用例边界 | S2 | REQ |
| `DM-n` | 数据模型条目 | S2 | REQ / IF |
| `ADR-nnnn` | 架构决策 | S1 / S2 / S3 | 相关 IF / DM |
| `DS-n` | 详细设计条目 | S3 | IF / DM / REQ |
| `WI-n` | 编码工作项 | S4 | DS / IF |
| `TC-n` | 测试用例 | S5（S3 只给测试点） | DS（可加 REQ / IF） |
| `RV-n` | 审查行 | S4 | WI |

## S1 · requirements.md（功能需求拷问的产物）

| 字段 | 内容 |
|---|---|
| `REQ-n` | 功能描述（一句话，可验证） |
| 验收点 | 怎么算做完了 |
| 来源 | 哪一轮拷问 / 哪次弹框 |
| 优先级 | 必须有 / 应该有 / 可以有 |

## S1 · nfr.md（非功能需求拷问的产物）

### 边界（第 1 轮）

| 项 | 答案 |
|---|---|
| 系统规模 | 现在多少用户 / 数据？峰值多少？ |
| 约束 | 多少时间？多少预算？有无合规标准？ |

| 字段 | 内容 |
|---|---|
| `NFR-n` | 问题（读写比 / 一致性） |
| 目标 / 答案 | 具体值或取向 |
| 为什么重要 | 一句话 |

### 质量_2（第 3 轮）

| 字段 | 内容 |
|---|---|
| `NFR-n` | 问题（增长预期 / 失败代价） |
| 目标 / 答案 | 具体值或取向 |
| 为什么重要 | 一句话 |

### 搭法（第 4 轮）

| 方案 | 做法 | 得到 | 放弃 | 倾向 |
|---|---|---|---|---|
| A | … | … | … | … |

> 第 4 轮的取舍，S2-8 正式写成 ADR。

## S1 / S2 · ADR（六块）

```md
# ADR-nnnn <标题>

- 状态：proposed | accepted | deprecated | superseded by ADR-nnnn
- 日期：
- 关联：REQ-n / IF-n / DM-n

## 背景
<问题、约束、当时的力量>

## 决策
<我们选了什么>

## 考虑过的其它选项
- 选项 A：…… → 否决理由：……
- 选项 B：…… → 采纳 / 否决理由：……

## 取舍与后果
+ <得到什么>
- <放弃什么>
- <留下什么技术债 / 触发条件>
```
